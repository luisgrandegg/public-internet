## Import Rules

Always import components from the design system package — never via relative cross-package paths.

```tsx
// ✅ Correct
import { Button, Card, Stack } from '@public-internet/design-system'

// ❌ Never do this
import { Button } from '../../packages/design-system/src/components/Button'
```

---

## Composition Rules

Apps compose, they don't define. Do not create one-off component wrappers.

```tsx
// ✅ Compose from design system primitives
<Card>
  <Stack>
    <Text variant="heading">Payment</Text>
    <Button>Pay now</Button>
  </Stack>
</Card>

// ❌ No styled wrappers or local component variants
const PaymentCard = styled(Card)`
  padding: 32px;
`
```

## Full-Stack Rules

Every app in this monorepo implements features end-to-end. Read [ADR-004](../decisions/ADR-004-full-stack-rest-api.md) before building any feature that touches data.

### Backend structure

Each app owns its backend inside its own directory:

```
apps/<app-name>/
├── prisma/
│   ├── schema.prisma      ← data model — commit every change
│   └── migrations/        ← never hand-edit; always generated by `pnpm db:migrate`
├── src/
│   └── app/
│       └── api/           ← REST Route Handlers (one directory per resource)
│           ├── auth/
│           │   ├── sign-up/route.ts
│           │   ├── sign-in/route.ts
│           │   └── sign-out/route.ts
│           └── listings/
│               ├── route.ts          ← GET (list) + POST (create)
│               └── [id]/route.ts     ← GET + PATCH + DELETE
└── .env.example           ← document every env var; never hardcode values
```

### Route Handler pattern

```typescript
// app/api/listings/route.ts
import { NextRequest, NextResponse } from 'next/server'
import { prisma } from '@/lib/db'
import { getSession } from '@/lib/auth'

export async function GET(req: NextRequest) {
  const { searchParams } = new URL(req.url)
  const listings = await prisma.listing.findMany({
    where: { city: searchParams.get('location') ?? undefined },
  })
  return NextResponse.json({ data: listings })
}

export async function POST(req: NextRequest) {
  const session = await getSession(req)
  if (!session) return NextResponse.json({ error: { code: 'UNAUTHORIZED', message: 'Sign in required' } }, { status: 401 })
  const body = await req.json()
  // validate body...
  const listing = await prisma.listing.create({ data: { ...body, hostId: session.userId } })
  return NextResponse.json({ data: listing }, { status: 201 })
}
```

### Server Action pattern (thin wrapper only)

Server Actions must call the Route Handler — they must not implement business logic themselves:

```typescript
// lib/actions/listings.ts
'use server'
import { revalidatePath } from 'next/cache'

export async function createListing(prev: ActionResult | null, formData: FormData): Promise<ActionResult> {
  const res = await fetch(`${process.env.NEXT_PUBLIC_API_BASE}/api/listings`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json', cookie: /* forward session cookie */ '' },
    body: JSON.stringify(Object.fromEntries(formData)),
  })
  if (!res.ok) {
    const { error } = await res.json()
    return { ok: false, fieldErrors: error.fields ?? {}, globalError: error.message }
  }
  revalidatePath('/host')
  return { ok: true }
}
```

### What is forbidden

```typescript
// ❌ Placeholder — returning ok: true without doing anything
export async function signUp(prev, formData) {
  return { ok: true } // does nothing — this is not a feature
}

// ❌ Mock data as a runtime data source
import { MOCK_LISTINGS } from '@/lib/mock-data'
// MOCK_LISTINGS is for Storybook and visual scaffolding only

// ❌ Business logic in a Server Action (cannot be called externally)
export async function createListing(prev, formData) {
  await db.listing.create({ ... }) // logic is trapped — not REST-accessible
}
```

### Database commands

```bash
pnpm --filter <app> db:migrate     # apply pending migrations (wraps prisma migrate dev)
pnpm --filter <app> db:generate    # regenerate Prisma client after schema change
pnpm --filter <app> db:reset       # drop + recreate (dev only)
pnpm --filter <app> db:studio      # open Prisma Studio
```

Add these scripts to each app's `package.json` when the database is wired up.

## Flagging Gaps

If a UI requirement cannot be met with existing design system components, **do not silently work around it**. Flag it explicitly and stop:

```tsx
// GAP: This requires a <Stepper> component not yet in the design system.
// Recommend adding to backlog before proceeding.
```

Then add the missing component to [`backlog/backlog.md`](../../backlog/backlog.md).
